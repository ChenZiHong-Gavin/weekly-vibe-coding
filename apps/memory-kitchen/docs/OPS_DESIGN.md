# 记忆厨房：可烘焙的备料

`src/ops.js` 按约定提供 `OPS`、`MIX`、`OP_PLAY_MS = 2200`、`planOp(op, seed)`、`createOp(op, input, seed)` 和 `createMix([target, dropped], seed)`。返回值为 `{ op, seed, plan, render, draw, tool, contours }`；没有接口偏差。只用 Canvas 2D，无运行时依赖、远程素材或 `Math.random()`。

每次创建操作都冻结传入画布的当前像素，不持有原照片；结果既是下一次的输入，也是舞台下锅碎片的纹理。`planOp` 只创建普通对象、数字和数组，在没有 DOM 的 Node 中可用。内部使用独立的种子哈希和 Mulberry32，避免 `state → ops → recipe → state` 的模块初始化循环。

## 八种操作

| 操作 | 物理动作与成品 | 顺序、重复时发生什么 |
| --- | --- | --- |
| 切片 / 菜刀 | 用带角度的平行半平面真正裁开当前像素；薄片滑开、轻微侧倾，刀口有亮面与右下投影。 | 再切时刀路穿过上一步已经错开的纹理。新种子改变刀路，交错切得更细；同一种子也会重新切开已移动的薄片。捣碎后再切得到的是泥条。 |
| 切丁 / 菜刀 | 两组正交刀路；沿第二组刀口逐块松开，小方丁轻微散落、旋转，每丁保留对应的画面。 | 原来的长条被横切成小块；重复切丁留下更多断面。先腌后切有新鲜亮刀口，先切后腌则在已有切缝上聚集湿亮边。 |
| 擦丝 / 擦丝器 | 把当前图像的细长采样带沿弯曲网格展开为 108 根细丝，分批从擦丝器下落，卷曲交叠。 | 处理薄片、软泥时，丝中仍是对应输入的纹理。已经很疏松的材料先收拢再喂入擦丝器，重复六次仍有丝堆。 |
| 捣碎 / 杵 | 大片颜色打散、低分辨率压成泥底；112 个来自当前像素的圆钝碎块有的沉入、有的留在表面，带压痕、湿光和短拖痕。 | 细丝捣后留下纤维与颗粒；切片捣后刀缝碎入泥里。先捣再切仍保留条状断面，先切再捣失去条形。重复捣使空间关系消失，但保留当前颜色和碎粒。 |
| 擀平 / 擀面杖 | 画面沿滚轴横向拖开，纵向压薄，形成宽薄片；边沿参差、破损、半透明，有细长拉痕。 | 擀丝得到压扁交错的丝层；擀好再擦则重新成为立体丝堆。再次擀会加长拖痕，并先收拢当前薄片的有效范围，避免高度指数缩到一条线。 |
| 腌制 / 碗 | 从当前像素的主要彩色中间调取汁色，自上而下有波动浸润线与流挂；保留对比，增加斜向光膜、挂珠、切缝积液。 | 刀缝、丝隙与盐晶也会被本轮湿釉覆盖。后切的边仍鲜亮，先切后腌的边较暗湿。暗输入略抬阴影，防止多次腌成黑块；黑背景不被误当作全部汁色。 |
| 撒盐 / 盐罐 | 图像略收紧、对比略增；不规则盐晶和少量暖色香料逐粒落下，晶面和少数星芒闪光。 | 盐只附着在材料的 alpha 上，不悬在切缝里。腌后撒盐的星点浮在湿釉上，撒后再腌则沉入光膜。重复撒会积累晶粒。 |
| 晾干 / 竹筛 | 缩小、偏暖褪色，边缘卷曲明暗、细裂与分叉；过程中有竹筛织纹的影子和日光。 | 湿釉会褪为较干的暖色表面；已有切口和纤维仍在。重复晾干保住有效面积，持续增加干纹，不靠白色覆盖褪色。竹筛和日光工具层不会烘焙进食材。 |

所有工具从案板上方观察：窄反光刀刃与铆钉木柄、起落木杵、带凸起孔口的金属擦丝器、有木纹的滚轴、倾斜釉碗和汁流、摇动盐罐、编织竹筛。工具的运动完全由 `u` 决定，`u >= 1` 不留下任何工具像素。

## 拌在一起

不是把两张照片做透明度叠加。先把两份**当前成品**各分成 16 个较大的纹理碎片。拖来的碎片悬在上沿，落到目标上；随后木勺绕过中间，把双方碎片抬起、压扁、翻折，交错放回。保留两张图中可辨认的局部，同时保留薄片的间隙、泥里的颗粒与细丝的弯曲。混合后的纹理可以继续用任意工具处理。

混合的起点按约定特殊处理：完整目标仍在原位，上沿露出待落的第二张图碎片；单输入操作的 `u = 0` 则与输入逐像素一致。所有操作的 `draw(u = 1)` 与 `render(size)` 完全一致。

## 保留质地，不累积空白

- 结果保留透明间隙，不把案板色、刀具、竹筛或整块阴影背景画进材料。
- 每次可重排当前材料的有效范围；已经擀薄的输入再次擀时会重整有效边界，而非连同旧留白再缩一次。
- 稀疏材料送入擦丝器、或者成为泥底前，以当前非透明像素作最近邻收拢，填补**采样纹理**的空洞。不会读取历史照片；泥表面的碎块仍保留原 alpha。避免反复对透明间隙取样导致食材消失。
- 泥底保留颜色区域而非反复用灰褐色覆盖；腌制对低亮度输入有有限补偿。多次擦丝、捣碎会失去照片细节，这是不可逆的结果，仍保留颜色和形态。

## 对接注意：透明度

`render()` 返回透明 Canvas。存储烘焙画面、`prev`、`prevB` 时应使用 **PNG**，例如 `canvas.toDataURL('image/png')`。JPEG 没有 alpha，会把刀缝、丝隙与薄片外部填黑；下一次工具就会把黑底误作材料，翻拌也会出现黑色方块。此要求适用于食材的中间态；最后的完整成品仍可用 JPEG。

本轮不修改 Claude 负责的 `kitchen.js`、状态、主流程、舞台和旧 `prep.js`。检查时 `kitchen.js` 的 `toUrl` 仍使用 JPEG；需由对接端改为 PNG。该点是存储格式要求，不是操作接口变更。

## 缓存与下锅轮廓

创建时只读当前输入的 64px 粗采样，分析有效范围、主要颜色和亮度。每个整数尺寸分别缓存工作纹理、裁好的刀片/方丁、卷丝网格、泥底、薄片、干纹、湿釉与最终结果。少数稀疏材料的收拢和薄片范围分析只发生在建立缓存时。逐帧只有绘制、变换、裁剪、投影和少量盐晶/工具路径；尺寸 512 的暖缓存动画检查中，8 种操作 `getImageData` 调用均为 0。

`contours(rng)` 使用单位坐标，切片与方丁对应实际移位后的刀路；擦丝为抽样的窄曲带；捣碎为软团；其余为撕开的片状碎块；混合为双方交错的碎片。每种都有有效的 `[0,1]` 多边形。无需改 `geometry.js` 的既有导出。

## 工具栏与卡片

只改 `style.css` 中工具和照片卡片规则：8 个工具固定 4×2、五个新增 SVG 厨具沿用灰绿金属与棕色木柄的手绘风格；照片为正方形；步骤用小号手写字；处理中卡片描出暖红边；混合落点出现虚线碗圈和「拌在一起 ↓」纸签。原有用量勺和其他页面区域不变。
