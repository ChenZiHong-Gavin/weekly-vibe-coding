# 页面里的锅 · Memory Kitchen

`src/potScene.js` 独立提供 `POT_OPS`、`POT_STEP_MS = 2600`、`DROP_MS = 1100`、`SERVE_MS = 2400` 和 `startPot(canvas, { reducedMotion })`。返回值严格为 `{ update, dropFrom, serve, dishRect }`，无接口偏差。没有引用 `stage.js`、`wok.js`，也没有运行时依赖或外部素材。

## 锅与食材

画面以 640×640 逻辑坐标绘制。光源在左上；卷边钢沿有方向性的金属反光、细划痕、暗槽和铆钉；内壁从远处暗面过渡到近处的暖灰反射，锅底有固定磨损颗粒。油膜和汤的反射沿用同一个光源。锅体、玻璃盖、三张体积水汽与小投影贴图只建立一次，在多个实例间共用。

每个输入的 `shape.polys` 就是入锅的真实轮廓，直接从当前 `src` 裁出纹理。不会回到原图，不会按烹饪方法重新切碎。非正方形原片按 cover 裁成正方形；PNG 的透明缝隙一直保留。

- `whole`：一整片照片，有薄厚度。
- `slice`：沿刀路裁好的长条，切口受光、底面较暗。
- `dice`：各个方丁保留对应的照片局部。
- `shred`：弯曲窄带，厚度比方丁小，保留照片丝堆的空隙。
- `mash`：圆钝软团，保留已经烘焙的颗粒。
- `flatten` / `dry`：一张撕边薄片，绝不拆成多个方块。
- `mix`：使用混合后的当前照片，按交错碎片落成一堆。

用量影响一把食材的大小。新下的每一把有按入锅顺序确定的落点，先保留多边形在案板上的相对布局。`dropFrom(id, DOMRect)` 的 CSS 屏幕坐标换算到锅画布；没有提示则从朝向案板的左上方落下。落锅时越过远锅沿，之后停稳；不循环漂动。

## 五个锅上动作

| 操作 | 物理表现 | 留下的状态 |
| --- | --- | --- |
| 煎 `sear` | 薄油反光、贴锅轻颤、细小滋泡和油点；不把整锅翻起来。 | 下缘及断面焦褐、细碎脆斑；大火比文火更深、更宽。 |
| 炒 `stirfry` | 带木柄的金属锅铲扫过，食材数次腾起、压缩翻面，落回后散开交错。 | 新的确定性落点和朝向、油亮的表面、少量褐变。 |
| 炖 `stew` | 动作初段添入一道汤，汤面扩大至锅壁，沸泡、缓慢对流、舀汤的勺与水汽。 | 汤位升高；已有食材的颜色进入汤色；食材纹理褪色、软化、略收缩、边角钝化。 |
| 蒸 `steam` | 从上方扣下玻璃盖；盖上有窗影、三百余颗冷凝水珠和弥漫水汽，末段揭盖。 | 表面变浅、湿润、边缘变软；锅里留下水分，不会凭空把原有汤倒掉。 |
| 收汁 `reduce` | 密集沸泡、大泡鼓起，汤面逐渐退向中央，露出锅底；短而厚的糖浆高光。 | 液位降至先前的 18%，变为深色浓釉；每块食材挂汁、颜色收紧。 |

火候属于每一个步骤。它影响火舌长度、煎的焦度、炖蒸的软化、沸泡数量与速度、翻炒腾起高度、水汽量和浓汁厚度。已用过火的锅在动作结束后保留静止的小火提示；没有动作时没有后台持续的火焰动画。

锅的液体单独重放：薄油 → 炖后较高汤位 → 收汁后低位浓釉；蒸留下湿度。更晚入锅的食材可以接触同一锅汤，但不会因此自动拥有早先的软化和焦化。

## 累积与顺序

每份食材只接收 `steps.slice(item.inAt)`。从冻结的当前图片出发，按步骤顺序处理颜色纹理、软化、褐变、湿润和浓釉，再烘焙各个碎片精灵。例如先煎后炖，炖会软化先前的脆边；先炖后煎则在软化过的纹理上留下新的锐利焦边。翻炒重排的结果也永久保留。

正常新增一步时，直接从上一步的缓存纹理与姿态继续，只保留动作所需的前后两套精灵，按进度渐变。恢复存档、重写历史时完整重放；首次 `update` 永远直接显示累计结果，不重演下锅或烹饪。跳过中间渲染而一次补进多步时，先累计到倒数一步，再播放最后一步。

`update` 对步骤键、火候、种子和食材身份进行比较；同一份声明不会重新裁图、布局或启动循环。食材移除后释放相应记录；新 id 加入后清除此前的成品。`id` 是持久身份，应保持唯一；下锅后形状和照片随食材冻结。

所有持久落点、斑点和粒子时相由固定种子计算，模块中没有 `Math.random()`。动画是绝对时间的解析函数，不依赖真实帧率、积分步长或回放速度。

## 出锅与对接

```js
const pot = startPot(document.querySelector('#wok-canvas'), { reducedMotion });
pot.dropFrom(id, card.getBoundingClientRect()); // 可选，紧接着新增 id
pot.update({ items, steps, heat, stage, dish });
await pot.serve(resultImageOrCanvas);
const { x, y, size } = pot.dishRect();
// x / y 是食物区的屏幕中心，size 是其直径，单位均为 CSS px。
// 飞行克隆的 left = x - size / 2，top = y - size / 2。
```

`serve` 用 2400ms 把食材聚向中心，逐渐缩小、融入成品；成品从中心扩展，最终铺满锅内食物区。结束才 resolve，随后保留在锅中。约定的 `stage: 'done', items: [], dish: src` 可以在刷新后恢复成品；同一会话中刚 `serve` 完，即使 `dish` 暂时为 null，仍保留刚才的图。下一份食材下锅才替换它。减少动态时所有动作直接跳到终点，`serve` 立即 resolve。

主流程负责按钮锁定、每步等待、下锅容量和持久化、最后成品计算与飞向盘子的 HTML 克隆；此模块只画锅。`style.css` 的 `.wok.is-over` 用暖色锅沿光和轻微朝案板倾斜反馈拖入，减少动态模式取消倾斜。五个 `.method` 按钮保持单排，新增煎与收汁的手绘 SVG 掩模，去掉烤和生拌图标；禁用时保留可辨的轮廓。

## 性能与验证

- 背景材质为共享缓存；输入纹理 448px；每个碎片只缓存紧凑包围盒内的照片、厚边、焦边和高光。
- 显示 backing store 上限 1280×1280，同时限制 DPR ≤ 2；`ResizeObserver` 处理响应式尺寸变化。
- 动作中只绘制缓存精灵、简单变换、有限气泡和水汽。投影使用小贴图，不为每片运行动态模糊。没有逐帧 `getImageData`。
- 动作结束后停止 rAF。普通静止、减少动态和反复 `update` 都不会产生常驻动画。
