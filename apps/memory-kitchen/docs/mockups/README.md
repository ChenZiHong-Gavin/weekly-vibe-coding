# 记忆厨房 · 单区布局视觉提案

四版均以 **1440 × 1000** 桌面画布呈现，直接用浏览器打开对应 HTML 即可；也可在项目根目录运行 `python3 -m http.server 8000`，访问 `http://localhost:8000/docs/mockups/v1.html`，替换版本编号查看其他方案。文件各自内联 CSS 和 SVG，无 JavaScript、动画、外部字体或网络依赖；按钮、选项和拖入提示仅示意位置与状态，不执行操作。

## [V1 · 围着一口锅](v1.html)

以居中的大锅为视觉圆心，三张照片沿锅边散放，处理方式贴着选中的照片，烹法与火候收进锅下的实体旋钮。定格在文火烹饪中，锅内有照片、汤汁与气泡，下缘小盘保留历史成菜和“放回锅里继续煮”的入口。它最接近现有手写菜谱本的亲切感，代价是自由摆放需要较多留白，食材增多时要控制环绕范围。

## [V2 · 摊开一张灶台](v2.html)

俯视一张连续的旧木桌面，照片摊在真实案板上，以刀、杵、腌碗、量匙和火苗承担处理方式、用量与火候，不使用软件面板式分栏。定格在刚出锅：锅中保留新记忆，右侧白瓷盘显示同一道成菜的装盘示意，保存与回锅像挂在桌面的纸签。实物隐喻最鲜明、厨房感最强，代价是需要文字标注帮助理解厨具与操作的对应关系。

## [V3 · 一道记忆的旅程](v3.html)

照片、刀工、大锅和盘子沿同一张连续台面向右展开，当前烹饪步骤放大，其他步骤缩小，用一条细线标明先后顺序。锅内三张照片正在交融，右侧使用成菜预览，回流虚线把盘子重新连回照片；配方集中在台面边缘的一行。流程和递归关系最清楚，代价是横向空间利用较满，沉浸感略弱于以锅为中心的方案。

## [V4 · 只留这一锅](v4.html)

让刚出锅的新记忆铺满深夜厨房的主体，大锅边缘延伸出画面，左下角留食材缩略图和当前食材的少量调味文字，右侧小圆盘用于回看。烹法、火候和动作退到底边，“放回锅里继续煮”成为最突出的下一步，强调成菜也能继续成为食材。它最安静、最沉浸，代价是照片亮度与控件对比需要细调，食材编辑的可见性也较低。

## 共用约定

- 延续米纸白、鼠尾草绿、旧木与砖红；标题采用本地宋体字体栈，批注采用本地楷体字体栈，系统未安装时回退至衬线字体。
- 图片仅引用本目录 `assets/`：`backlit.jpg`（窗边的午后）、`kid.jpg`（第一口笑）、`lowkey.jpg`（那束光）作为食材，`dish.jpg` 作为成菜。历史盘、装盘示意与成菜预览复用同一张成菜图片，不代表多次生成了不同结果。
- 四版都呈现照片多选与最多五张的提示、选中食材的改名与味道、三种处理方式、三档用量、五种烹法、三档火候、菜名、开火状态、保存、再来一锅、回锅、历史回看，以及右上角灶台设置入口（生图接口）。烹饪中的 V1、V3 将开火按钮显示为已开火状态；刚出锅的 V2、V4 保留下一次开火的入口。
- 所有内容只用于选择构图方向，正式产品逻辑仍按 [BRIEF.md](BRIEF.md)。本次仅新增四个 HTML 和本说明，未修改 `src/`、`index.html`、`tests/`，未提交 Git。
