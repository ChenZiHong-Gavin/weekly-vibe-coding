# MIND HOP · 附身潜入

浏览器里的第三人称潜入游戏。核心不是打，是**附身**。

> 琴没有超人的体能：走得不快、跳不高、挨不了几下。
> 她唯一的能力是把意识送出去 —— 而那时候，**这具身体就留在原地，毫无防备**。

> 在线试玩：https://chenzihong-gavin.github.io/weekly-vibe-coding/mind-hop/
> 本项目是 [weekly-vibe-coding](../../README.md) 的第 20 个 app。

## 跑起来

```bash
npm install
npm run dev        # http://localhost:5178
```

必须走本地服务（`file://` 会被跨域策略拦掉 ES 模块和 GLB）。点击画面锁定鼠标，`Esc` 退出。

## 两个视角，两套操作

游戏在两种操控对象之间整体切换 —— **包括相机和控制方案**。
左上角的控制面板是上下文相关的：只列当前这具身体能做的事，切换时整块换掉。

| | 本体 | 宿主 |
|---|---|---|
| 你操控 | 琴自己 | 被附身的那个人 |
| 相机 | 琴身后 | 那个人身后（`V` 切第一人称） |
| 画面 | 暖色余烬轮廓 | 轻微去饱和 + 紫色念力反光 |
| 能做 | 走、跑、投射意识 | 换宿主、撤回、喊叫/开火、读记忆 |
| 风险 | 慢，走不远 | 身体留在原地，被人看见就完了 |

意识飞行的那 0.2–1 秒里，相机跟着那道余烬走。

### 本体监视窗 —— 可以操舵的窗口

附身在外时，右下角有一个持续盯着自己身体的画中画。它不只是给你看的：
**两套操作严格分离**：`WASD` 永远操控"你穿着的那具身体"，`方向键` 永远操控
"你自己的身体"。两者可以同时进行 —— 一手推进渗透，一手把身体往阴影里挪。

（早先把方向键混进了 WASD 的输入，结果一按方向键宿主和本体一起动，
完全说不清在操谁。现在交叉验证是硬断言：本体不响应 WASD、宿主不响应方向键，
两条都必须为 0。）

意识不在身上，所以身体走得像梦游：**1.15 m/s**（正常走路 2.4 的一半不到），
转身也是钝的，姿态介于"投射"和"走路"之间。慢到「把身体搬到城市另一头」
依然昂贵，快到「趁没人时挪进旁边的巷子」是可行的 —— 于是原来那个硬中断
（必须撤回、走过去、再投射）变成了一个持续的、有风险的微操作。

两个必要的细节：

- **转向相对监视窗**，不是主相机 —— 你是看着那个小窗口在操舵的
- **操舵时环绕冻结**：参考系一直转的话根本没法照着窗口按方向键；
  松手才恢复环绕（边框同时变紫，提示"你正在操舵"）

这也是把「身体留在原地」从一个数字变成**看得见的东西**：

- 监视相机缓慢环绕，被墙挡住时自动换一个通视角度
- 有守卫看见那具发光的身体 → 边框变红，并写出他还有多远
- 而且他会**真的朝那具身体走过去** —— 暴露度按接近程度加权，
  站到身体旁边时涨得最快

（这里踩过一个坑：最初守卫看见本体只是加怀疑度，然后转头去追远处的宿主，
反而把本体看丢了 —— 监视窗因此完全没有紧张感。现在看见就会锁定几秒。）

## 操作

| 键 | 作用 |
|---|---|
| `WASD` | **操控你附身的那具身体** · `空格` 长按跑 |
| `方向键` | **操控你自己的身体** —— 意识在身上时是正常走动；在外时是看着右下角监视窗"梦游操舵" |
| `E` | 附身最近的目标（约 13m，接近原作的 30 英尺） |
| `X` | 撤回本体 |
| `左键` | **用这具身体做事** —— 平民喊叫制造骚乱；DODC 朝同僚开火 |
| `F`（长按） | 读取宿主的记忆 |
| `V` | 宿主视角下切换第一/第三人称 |
| `Tab` | 音频设置 · `M` 静音 |
| `R` | 重开 |

走是 2.4 m/s、跑是 5.6 m/s。**跑起来很显眼** —— 守卫看见跑动的人会起疑，
所以在禁区附近你会自觉地走。没有跳跃：琴是个普通人，这座城市也没有需要跳的地方。

## 玩法

### 阶段一 · 追溯
人群里藏着 **3 个知情者**，地图上没有标记。只有**心灵回响**：38m 内能感觉到方向，
13m 内才显形。附身他们、长按 `F` 读记忆。附身任何人都能读到一句心声，
但只有那三个人身上有线索。

### 阶段二 · 渗透
三条线索拼出 DODC 设施的位置。禁区里的**平民会被守卫喝止**——
必须附身一名守卫走正门。守卫扎堆的地方不好下手，附身一个平民走远点、
按 `左键` 喊一嗓子把守卫调开，再挑落单的那个。

### 阶段三 · 撤离
拿到档案，把意识带回本体。

### 两条会要你命的资源

**链条稳定度** —— 离本体越远衰减越快，`perJump / (3.0 + 0.085·d)`：
20m 外 3.3 秒一跳够用，110m 外要 1.2 秒一跳。归零就被强制弹回，还会眩晕。
所以真正的战略层是：**你得时不时撤回来，亲自把身体挪近一点**——
而挪过去的路上，她是个走得很慢、发着光的普通人。

**暴露度** —— 本体附近的恐慌会把 DODC 引过来；被守卫制服、拉警报、
当众附身被平民看到都会加。守卫如果**直视到正在投射的本体**（一动不动还在发光），
暴露度会飙升。满了就输。

### 附身是看得见的

跳进（和跳出）一个人的瞬间，那人会眼神一空、猛地一个趔趄。**旁边的人会看到这一下。**

- 视野内（34m、有视线、且他确实朝这边）的每个守卫，怀疑度一次性 +26；
  被跳的人自己穿着 DODC 制服 → ×2.1 = 55，直接触发喝止。
- 13m 内的平民会转头看过来，近的那几个直接退开；每人给一点暴露度（0.55）。
  人群密度中位是 3 个人 —— 所以在人堆里连跳基本被暴露度的自然回落抵消。
  **人群是掩护，守卫才是威胁。**

准星会提前告诉你答案：目标被谁盯着的时候，框变红，下面写「N 双眼睛看着」。
这一条是「制造骚乱」存在的理由 —— 在这层之前，附身零代价，
你从来不需要把守卫引开，那个左键就是个多余的按钮。现在的循环是：

> 看到目标被盯着 → 找个远处的平民喊一声 → 守卫离岗赶过去 → 目标干净了 → 跳。

### 会踉跄

被附身的人在**进入和脱离**时都会踉跄一下 —— 上身失衡、手臂外张、脚下打绊。
这不只是演出：踉跄期间你的操控只剩 18%，而守卫看见一个走路发飘的人就会起疑。
脱离之后那人会断片一秒多，然后惊慌逃走，**永远不会回来**。
你穿过的那条街，人是真的会变稀。

## 技术要点

### VAT 人群渲染 (`world/crowdRender.js`)
320 个带骨骼动画的角色不可能各自 `SkinnedMesh`。动画在 CPU 上烘焙成纹理，
运行时一个 `InstancedMesh` + 自定义顶点着色器采样：分块布局（顶点数超过 2048
按行折叠）、半浮点位置 + 字节法线。**339 个动画单位、7.4M 面、约 120 fps。**

被玩家附身的那一个会从 VAT 里"取出来"，换成真正的蒙皮网格 ——
近景要看得清踉跄，要有平滑的动画混合。

### 跨绑定姿态 · 跨 T/A-pose 的动画重定向 (`core/retarget.js`)
走跑待机全部来自 Xbot，重定向到 Michelle 和 readyplayer.me。语义是
**让目标骨骼的肢体指向与源骨骼一致**：

```
W_M(b) = W_X(b) · K(b)
K(b)   = 把「目标骨在自身绑定局部系里的肢体轴」转到源骨对应轴的最短弧
q_M(b) = inv(K(par)) · q_X(b) · K(b)     根骨另加 inv(P_M)·P_X 吸收坐标系差
```

这条路上有四个坑，每个都单独踩过：

1. **不能直接复制局部旋转** —— Xbot 与 Michelle 的肩骨局部轴相差 90°，
   直接复制会把手臂抬到肩膀以上。
2. **不能保留「相对绑定姿态的形变量」`D = W·inv(Bind)`** —— D 保留的是*增量*。
   Xbot 以 T-pose 绑定，走路时手臂从水平下摆约 75°；readyplayer.me 却是
   **A-pose 绑定**（上臂本来就朝下），再叠加 75° 就甩过身体 —— 这就是
   "礼帽男两只手反了"。Michelle 也是 T-pose 绑定，所以同一个 bug 在她身上
   完全看不出来，藏了很久。
3. **Bind 必须取自 `inverseBindMatrices`**，不是节点的 rest transform —— 两者可以
   完全不同。
4. **肢体轴只对单子骨有意义** —— Hips 同时连着脊椎和两条腿，取"最远子骨"在两副
   骨架上可能选到不同的骨，算出的修正会把整个身体拧歪。躯干退回绑定差即可。

### 手臂内收
Xbot 的走路动画本身上臂就外张 **26°（峰值 34°）** —— 那是个机器人模特的步态，
重定向是忠实的，所以三个模型都一样"摊着手走路"。
修正放在动画之后（`core/rig.js: adductArms`）：把上臂的世界指向朝正下方旋转 14°，
用世界方向算，不依赖任何一副骨架的局部轴约定。走路 26° → **12°**，待机 13.5° → **1.1°**。

人群的 VAT 是在初始化时烘焙的，所以**烘焙循环里也要应用同一个修正**，
否则满街还是摊着手的人。判据见 `armangle.mjs`。

### 角色多样性
三种网格：Michelle（年轻女性）、readyplayer.me（西装礼帽男）、Soldier（DODC）。
在此之上做程序化变化：**身高 1.52–1.96m、体型宽窄 0.88–1.14、色相旋转换装**。

换装用**色相旋转**而不是乘色调 —— 乘色调会连肤色一起染，浅色衣服还会被洗成一片白。
旋转色相保留了贴图的明暗结构，看起来真像换了一身衣服；近灰区域（白衬衫、黑裤）
按饱和度加权跳过，不然会显得脏。

琴不共用这套变化：她走定向重染（赤褐头发 + 深酒红夹克 + 深裤 + 常驻余烬轮廓），
分带用**世界高度减脚底高度**，与模型的建轴无关 —— Michelle 的几何体是 Z-up 的，
按 `position.y` 分带会全部落空。

### 距离剔除
城市跨度 267m，但雾里只看得到 ~120m。人群超过 78m（守卫 110m）不写渲染实例，
**仿真对所有 agent 照跑**，知情者和当前锁定目标永不剔除。
渲染单位从 487 降到 44–167，面数 11.8M → 5.6M，帧率 56 → 120 fps。

### 音频：听觉是情报 (`audio/`)

全部音效**程序化合成**，没有一个外部音频文件 —— 和城市窗户、天空一样，
在初始化时算进 `AudioBuffer`（24 个音源，`audio/synth.js`）。

四条总线（音效 / 环境 / 音乐 / 界面）→ 主总线 → 限幅器 → 输出。
限幅是必需的：几十个声音叠在一起会削波。音量设置持久化在 `localStorage`。

不用 `PannerNode`，自己算距离衰减 + 立体声摆位 + 遮挡低通，因为需要**两只耳朵**：

> **★ 双耳设计** —— 附身在外时玩家的耳朵在宿主身上，但**本体那边的声音也必须听得见**。
> 靴子正在靠近那具毫无防备的身体，这是最关键的情报。所以每个声音同时按
> 「相机」和「本体」算一次可听度，取更响的那个；走本体耳朵的声音会被压到
> 2.6kHz 以下，听起来像隔着另一具身体传来的 —— 一听就知道"这是我身体那边的动静"。

实测：宿主在 70m 外时，本体旁 2m 的靴子声以 **0.70 增益 / 2600Hz** 传来，
而同一个声音贴着宿主时是 **0.85 增益 / 19186Hz**。来源可分辨。

其它让声音真正承载信息的地方：

- **靴子 vs 便鞋**：DODC 的靴子更重、更闷、传得更远（42m vs 28m）——
  你能靠声音判断走过来的是守卫还是路人
- **遮挡**：隔着一整栋楼，靴子声从 14072Hz 被闷到 2590Hz（听得见拐角后的脚步）
- **步频跟速度**：跑起来更密
- **喝止**：守卫起疑时会喊，位置可听
- **心跳**：暴露度 / 被怀疑 / 有人靠近身体三者取最大值驱动，越紧张越快
- **人群低语**：音量随 30m 内人数，明亮度随人群密度；恐慌骤增时有一层扑上来的噪声
- **音乐**：四层缓慢漂移的持续音，音量随任务阶段、明亮度随紧张度

### 人群仿真 (`world/crowd.js`)
Helbing social force model 跑在 XZ 平面：驱动力、各向异性指数斥力、
接触与摩擦、建筑墙力。状态机 `calm → stumble → stun → panic`，
恐慌以 1.7/s 在 2.4m 内传染。附身者自身斥力打三折但**别人对他满值避让**，
所以人群会为他分开。

### 守卫 (`world/guards.js`)
不是靶子，是眼睛。怀疑度来自：走路发飘的人、闯禁区的平民、跑太快的人、
以及**直视到投射中的本体**。怀疑满且贴近就上前制服，把你从宿主里赶出去。
骚乱会让他们离岗 —— 那是唯一的窗口。

```bash
node rendertest.mjs    # 渲染真实性：画出来的实例数与位置必须对得上仿真（幽灵实例）

```

`dirtest.mjs` 是因为踩过坑才加的，而且踩了两次：

1. 相机里的 `_d` 是「从角色指向相机」（背后），当前方用 → W/S 反。
2. 右向是 `forward × up = (-fz, fx)`，写成了 `(fz, -fx)` → A/D 反。

第二次尤其值得记：测试脚本里算 `right` 用的是同一个错公式，于是它自证清白了。
所以现在的判据不再依赖自己推导的向量，而是**投影到屏幕空间**——
按 D 角色就该往画面右边走，按 W 就该往画面深处走。这个判据没法自洽地错。
换算统一走 `core/utils.js: camRelative()`，不在两处各写一遍。
`rendertest.mjs` 也是踩坑才加的，而且是最贵的一个坑。

玩家反复报「有人卡在原地不动 / 卡在墙里」，我改了五轮 AI：加卡住计时器、
让岗位保证在楼外、给目标选点加视线检查、给站桩的人加重心挪动……全都测过、全都变好了。
真正的原因是 `suitVat.setCount(si)` 这一行**从来没被调用过**（一次字符串替换只落了一半）。
`InstancedMesh` 默认 `count = max`，于是西装男仿真只有 124 个、却画出 328 个，
**318 个定格在旧位置的幽灵实例**。玩家指的那些"不动的人"，一个都不在仿真里。

之前每一个测试都在量仿真，没有一个量"画出来的是什么"，所以全都是绿的。
用户还提出过是不是「卡帧」—— 帧时间中位 8.3ms、没有一帧超 33ms，不是卡顿；
但正是这个方向让我去测了渲染层，才撞上真正的原因。
**教训：仿真正确不等于画面正确，回归里必须有一条断言站在渲染这一侧。**

"礼帽男走路奇怪"最后查出来是两个独立缺陷，而且都不只影响他：

1. **`adductArms` 分不清外张和摆臂。** 它把上臂朝"正下方"旋转 14°，可手臂
   前摆 30° 时与正下的夹角也是 30°，于是照样被压回去 —— 摆臂幅度从 46° 剩
   25.8°，走起来两只手像钉在胯上。现在按身体坐标系分解（`right` 取左肩→右肩，
   跨骨架都可靠），只收冠状面内的外张，矢状面的前后摆原样保留。
2. **重定向把 Hips 的位移轨道整个丢掉了。** 理由曾经是"位移＝根动画＝角色会
   飘走"，但 Xbot 的走路是**原地循环**：前后分量恒为 0，丢掉的是 4.4cm 上下
   起伏 + 4.8cm 左右重心转移。结果胯高幅度恒为 0，人是滑过去的；而且 Mixamo
   的腿部角度本来就是和胯部起伏一起编的，抽掉起伏支撑脚就踩不住地。
   现在按"首尾接近＝周期性、单调漂移＝根动画"逐轴判断，只搬周期性的那部分。

第 2 条的缩放比连错两次，都值得记：
- 用**绑定世界胯高之比** → 三副骨架胯高都 ≈1m，比值 ≈1，于是 4.4 个"厘米"
  被当成 4.4 米加上去，礼帽男直接起飞（胯高幅度 3.897m，脚在 ±2m 之间乱飞）。
  位移轨道的数值是**局部单位**：Mixamo 的 GLB 在 Armature 上挂 0.01（厘米→米），
  readyplayer.me 没有这层。
- 改用 **Hips 静止局部高度之比** → 对 Michelle 是垃圾：她的 Armature 带 90°X
  旋转，Hips 局部 Y = **-0.52**，那根本不是身高方向。

正确的量是**根骨父节点的世界缩放之比 × 绑定世界胯高之比**：世界缩放不受骨架
朝向影响，是这里唯一可靠的东西。

`public/retest.html` 是动画重定向的并排验证页（左 Xbot 原生 / 右 Michelle 重定向）。

## 加载体积

首屏 **约 1.4MB**（JS gzip 后 247KB + Michelle 890KB + Xbot 283KB），本机 0.8 秒可玩；
DODC 和第二种平民的外观（1.7MB）在开局之后后台补齐。

模型原始件 9.7MB，`node tools/optimize-models.mjs` 之后 **2.8MB（-71%）**。
省下来的绝大部分不是压缩，是**删掉游戏根本不用的东西**：

| | 原始 | 之后 | 砍掉的是什么 |
|---|---|---|---|
| `Xbot.glb` | 2.79MB | 0.28MB | 它只是**动画源**，网格从不渲染；另外 4 个片段没人用 |
| `Michelle.glb` | 3.13MB | 0.87MB | `SambaDance` + `TPose` 共 1.36MB，代码一次都没碰 |
| `Soldier.glb` | 2.06MB | 0.84MB | `TPose`；纹理转 webp |
| `readyplayer.me.glb` | 1.75MB | 0.84MB | 19 张纹理转 webp 并限制边长 |

这一步踩了四个坑，都值得记：

1. **`prune()` 不会回收被丢弃动画的 accessor。** 光调 `animation.dispose()`，
   Michelle 的动画数变成 0、accessor 却还是 399 个，1.37MB 的 SambaDance
   继续躺在文件里（只瘦了 22%）。要显式 dispose 采样器指向的 accessor，
   同时避开被保留片段共用的那些。
2. **Xbot 的网格不能直接删。** 它确实从不渲染，但 `captureBind` 要从
   `SkinnedMesh.boneInverses` 读绑定姿态。删掉 mesh + skin 之后，`prune` 又把
   骨骼节点当空叶子清了，结果 Michelle 整个僵在 T-pose（膝角 0°、步幅 0.006m）。
   正解：用 `simplify()` 把网格砍到 1%，但保住 skin 和骨架。
3. **`quantize()` 会改写 `inverseBindMatrices`。** 它把 POSITION 压进整数区间、
   再用节点变换和绑定矩阵补偿，于是绑定世界胯高从 1.03 变成 0.24
   （Soldier 更夸张，1.15 → 0.0155）。凡是拿 `bindPos` 当**物理尺寸**用的地方
   都会崩 —— 走路的上下起伏因此从 4.4cm 掉到 1.0cm。骨骼层级本身没变，
   所以身材比例要取 `getWorldPosition()`。（限位轴仍用 `bindPos`：量化对同一
   模型是等比的，方向不受影响。）
4. **不注册扩展就会静默丢材质。** 不传 `ALL_EXTENSIONS`，
   `KHR_materials_specular` / `ior` 在写回时无声消失。

## 踩过的坑（都有对应的回归脚本）

1. **WASD 四个方向全反** —— 相机里的 `_d` 是「从角色指向相机」（背后）；
   右向是 `forward × up = (-fz, fx)` 而不是 `(fz, -fx)`。
   更值得记的是：`dirtest.mjs` 最初用了同一个错公式算 `right`，于是**自证清白**。
   现在判据改成投影到屏幕空间 —— 按 D 就该往画面右边走，这个判据没法自洽地错。

2. **两个判据互相矛盾时，先怀疑推导** —— 查朝向时我写了肩部判据和脚趾判据，
   四个模型上结论全部相反。错的是我把 `right = forward × up` 写成了
   `up × forward`。数据没问题，推导有问题。

3. **GLTFLoader 会去掉骨骼名里的冒号** —— `mixamorig:Hips` 变成 `mixamorigHips`，
   而不同模型的前缀还不一样（readyplayer.me 直接叫 `Hips`）。
   写 `replace('mixamorig:','')` 会静默匹配不到任何骨骼：没有报错，只是**所有程序化
   姿态叠加变成空操作**（踉跄和投射姿态一直是死的），而且重定向出 0 条轨道。
   统一走 `core/utils.js: boneName()`，装配后自检骨骼数为 0 就告警。

4. **Mixamo 根节点旋转不统一** —— Soldier 是 -90°X、Michelle 是 +90°X，相差 180°。
   VAT 烘的是世界空间顶点，于是一半模型倒着走。烘焙时按脚趾/脚跟的 Z 关系探测并规范化。

5. **意识飞行途中目标失效 → 硬死锁** —— `recall()` 第一行 `if (this.busy) return`
   把从 `P_TRAVEL` 转向的路堵死了，意识永久卡在传输态。

6. **相机会钻进建筑** —— sweep 有 0.35m 下限，墙比这更近时相机就在墙里。
   最终兜底：`#pushOutOfWalls()` 沿最浅轴把相机顶出去。

7. **`Box3.setFromObject` 不能用来量蒙皮角色** —— 根节点的 ±90°X 旋转会被绑定矩阵
   抵消，那样量出来的是模型厚度。必须量 `applyBoneTransform` 之后的顶点。

8. **共享临时向量别名** —— `fireBullet(from, to)` 里 `from` 正是调用方传进来的模块
   级临时向量，函数内 `copy(to)` 把它一起改了 → 速度恒为零。

9. **忠实的重定向也可能看着不对** —— 三个模型走路时上臂外张角完全一样（26°/34°），
   正好证明重定向没问题、**源动画本身**才是问题。修正加在动画之后，
   而且 VAT 的烘焙循环里也要加，否则人群保持旧姿态。

10. **`rig.overlay()` 是「rest × 偏移」，而 rest 就是 T-pose** —— 这一条坑了两次。
    它直接写 `bone.quaternion = rest × 偏移`，所以：
    (a) 任何在它之后应用的修正（比如手臂内收）会被静默抹掉；
    (b) **偏移给 0 手臂也会弹回平举**（实测 92.4°，正好 T-pose）。
    而且手臂骨的局部 Z 轴不是外张轴 —— 给 −1.25 得 76°、给 +1.30 得 96.8°，
    大部分旋转变成扭转，怎么调都不对。
    结论：**程序化姿态一律不碰手臂**，只动脊椎/颈/头（它们的 rest 接近单位四元数）。
    手臂交给动画层（那一层已内收）。真要动手臂就得像 `adductArms` 那样在世界空间算。
    判据见 `posetest.mjs` —— 在真实游戏里量六种状态，不看截图猜。

11. **满值不锁定 = 条件永不触发** —— 暴露度达到 100 的那一帧，同一次 update 里
    后面的自然衰减先把它压回 99.96，于是失败判定永远不成立，那条槽变成永远填不满。
    达到上限必须**立刻锁定终局状态**。

12. **把两套输入混进同一个轴** —— 早先为了省事把方向键别名进 WASD 的轴，
    结果一按方向键宿主和本体一起动。现在交叉验证是硬断言：两条都必须为 0。

13. **静默的字符串替换是 bug 工厂** —— 锚点文本漂移后替换失败却不报错，
    于是"改完没生效"。要么断言锚点命中，要么读回文件确认。

14. **同一个"测试自证清白"的陷阱踩了第三次** —— 监视窗操舵反了 180°
    （`G.pipYaw = atan2(-sin ang, -cos ang)` 就是 `ang + π`），而 `dirtest`
    和 `dragtest` 都用同一个公式从 `G.pipYaw` 反推"期望前向"，于是双方一起错、
    测试全绿。现在判据从**真实的 `pipCam.matrixWorld`** 取。
    修完还把 bug 放回去验证测试确实会报错 —— 不然不知道这个判据到底有没有用。

15. **"不让你做又不说为什么"读作游戏坏了** —— 原本 7% 的路人是"增强人类"，
    附身会被弹开。但他们外观上毫无区别，玩家只会觉得"这个人有 bug"。
    已删除。想保留这一层，得先让他在外观上可辨。

16. **没有寻路就要有卡死兜底** —— 目标落在建筑对面的 agent 会一直顶着墙推，
    街上于是留下几个"站着不动的人"。现在几乎不动超过 1.6s 就重选目标，
    并且优先选 70m 内的点（直线路径更可能是通的）。

17. **`pushOut` 单趟是不够的** —— 街区里的楼是挨着排的，把点推出一个盒子的
    同一步很可能把它推进相邻的盒子。单趟只保证"离开了第一个盒子"，结果有
    **8 个守卫的岗位落在设施楼内部**，他们站在楼里一动不动。
    现在迭代最多 8 趟，再用螺旋搜索 `nearestFree()` 兜底确认。

18. **"一动不动"这个判据我写错了三版** ——
    (a) **速度阈值**：原地抖动的 agent 速度不为 0 但一步没走 → 漏。
    (b) **累计路程**：踱步的守卫路程够长 → 漏；
    (c) **净位移**：一个人走出去 8m 再走回来，净位移只有 1m 但完全正常 → 误报。
    对的判据是**连续**低位移增量的时长（step < 3cm 持续多久）。
    换成它之后立刻定位：平民 0 个超标，**20 个守卫全部超 2 秒，最长 8.2 秒**。
    而且前两版我只扫了 `crowd`、忘了 `guards` —— 问题全在守卫身上。

19. **"卡在墙里"的观感可能不是穿墙** —— 实测无人中心在建筑内（最小墙距 0.52m），
    真正的原因是守卫**完全静止**且离墙不到 1m。一个纹丝不动的人形贴着墙，
    就会被读作"卡在墙里"。三层修复：岗位保证在楼外、在半径 7.5m 内踱步、
    **停留时也小幅挪重心**（站着不动才是问题的核心，光缩短停留时长不够）。
    最长静止 8.2s → 2.2s，静止超 4 秒的 14 人 → 0。

20. **没有寻路时，选目标要检查视线** —— 随机 walkPoint 常落在楼后，agent 一路顶墙，
    被 stuck 逻辑救起后又挑到另一个墙后目标，来回乒乓（最差的 15 秒走 17m、
    净位移 0.15m）。现在候选目标必须满足"前 25m 直线通畅"，
    全不通就退化成"朝最开阔的方向先走一段"脱离墙角。
    路程最小值 4.2m → 9m（每个人都真的在走）。
